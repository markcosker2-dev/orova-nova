Documented Nova Drive backup integration

Privacy notice.

Mark operates this private MikeBot integration for OROVA. Contact markcosker2@gmail.com with access, correction, deletion or security questions.

Data accessed and purpose

The documented integration uses Google Drive file access (drive.file) to create, list, read and recover application-accessible backup files. File metadata and database contents are processed for backup, integrity checking and restoration.

Database snapshots may include business contact details, lead status, internal activity, approval and conversation records. A partial recovery file may omit some of these records; it is not represented as a complete backup.

Storage and access

Backup files are stored in the owner's Google Drive. Authorized recovery downloads can be stored on the owner's computer and restored to Nova's private operating environment on Render. OAuth credentials are kept in access-restricted settings or private local files, not this public information site.

The backup transport sends file data to Google and downloads it for authorized recovery. Its code does not send backup contents to an LLM. Broader Nova features and the second client sharing this Google project require a completed data-flow disclosure before this draft can become an app-wide policy.

Retention and your controls

There is no verified fixed deletion deadline. Automatic backup pruning is disabled by default in the prepared release; when expressly enabled, its retention routine moves older snapshots to Drive Trash. Revoking Google access stops future authorized access but does not erase existing Drive files or private recovery copies. The owner can delete or request removal of those copies separately.
