## 2. THE headline: durability is fixed

The 2026-08-09 handoff called this the highest-value unknown and framed it as
*"is the write lying, or is the read looking in the wrong place?"*

**Neither.** Every `append_row` was writing to `Leads!A2:L2` and overwriting the
previous lead:

```
append -> updatedRange='Leads!A2:L2' business='HEARTWOOD BUILDERS INC'
append -> updatedRange='Leads!A2:L2' business='PEAK BUILDERS INC'
append -> updatedRange='Leads!A2:L2' business='LEWCO CONTRACTING'
```

`gspread.append_row` relies on Google's table detection from A1, which resolved
to the header and returned row 2 every time. So `Sheets: 5/5 leads synced` was
true and worthless at once, and **every restore recovered exactly one lead
because there was only ever one row.**

Now prints on every hunt:

```
✅ verified: sheet holds N rows covering N distinct businesses
```

**Deploys are no longer data-loss events.** This is the single biggest change.

## 5. ICP qualification — settled with measurements

Free, keyless, joined on `ubi`:

| dataset | id | gives |
|---|---|---|
| Licences | `m8qx-ubtq` | name, principal, phone, trade, entity type, UBI |
| Principals | `4xk5-x9j6` | named principals — **58.9% have exactly 1** |
| Insurance | `ciwg-agsx` | GL cover — **88.4% carry exactly $1M, 7.9% more** |

**Two different questions:** principal count measures *urgency* (payroll is an
external deadline); insurance cover measures *affordability* (cover scales with
job size).

**Solo is a discount, not a disqualification.** Of 300 contractors carrying
above the minimum, **126 (42%) are sole operators** — they can pay. The Retell
script now branches (`solo` / `has_crew` / `unknown`) rather than disqualifying.

Selection is a **band**: licensed 3–25 years, not `Individual`, ≤8 principals
(the "already has an in-house team" exclusion), sole owners ranked first, then
by cover. **8,768 qualify** in the target cities ≈ 3.4 years of outreach.

There is **no free payroll signal** — WA's only workers-comp dataset is
aggregate claim rates.

## 8. The lesson worth carrying

Three confident mechanisms were wrong before the right one was found —
duplicate collapse, duplicate workbooks, a read-after-write race. Each explained
most of the evidence. The answer came from **capturing a field the API had been
returning all along** (`updatedRange`).

> When a mechanism explains most of the evidence but not all of it, it is wrong.
> **Instrument, don't theorise.**

Its sibling, from the same day: **a mock easier to satisfy than production is a
decoy, not a test.** The verifier that would have caught all of this crashed on
every production run for weeks while its tests passed, because they mocked
`fetchone` with a dict and production returns `sqlite3.Row`.
