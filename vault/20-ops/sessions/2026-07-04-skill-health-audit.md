# Skill Health Audit (2026-07-04)

Read-only diagnostic pass over every module in `app/skills/` (51 files). For each:
tried a clean `importlib.import_module`, read the code for entry points and
`os.getenv`/import dependencies, and — where a function can run fully offline
(no network, no key) — smoke-ran it with trivial safe inputs. No real email,
calls, or paid API hits were triggered. `app/core/ai_client.py`'s
`UnifiedAIClient` (Groq → Gemini → OpenRouter chain, all currently dead) never
raises: on total failure it returns `content="[!!] No AI providers available."`
(or "...All AI providers failed...") as a normal string, so most AI-touching
skills degrade to a visibly-broken-but-non-crashing report rather than an
exception. Skills are flagged per-skill below wherever that matters.

## Totals

- **51 `.py` files** under `app/skills/` (including `apollo_scraper/__init__.py` + `apollo_scraper/scraper.py`).
- **Import health**: 49 import cleanly / **2 broken** (`browser_use_skill.py` — missing `browser_use` package; `mem0_skill.py` — missing `mem0` package). Both fail at `import`, not at call time, so any code path that imports them (directly or transitively) will crash before reaching the LLM-dead-key question.
- **Needs a key/credential to reach full functionality**: the majority of hunt/enrich/outreach/calls/CRM skills (Apollo, Tavily, Firecrawl, SerpAPI, RETELL_*, AGENTMAIL_API_KEY, Google OAuth/service-account creds, Telegram, Meta access token) — but nearly every one of them was explicitly written to **degrade to a clean skip/fallback rather than crash** when its key is absent. This "fail soft on missing creds, fail closed on AI/logic errors" pattern is consistent across the whole codebase.
- **LLM-dependent skills under the current dead-key state** (Groq/OpenRouter/Google all failing): confirmed via direct smoke test that `copywriting_skill.write_cold_email` and `outreach_orchestrator.compose_premium_outreach` both degrade non-fatally — the former embeds a visible `[!!] No AI providers available.` placeholder (no template safety net for `write_ad_copy`/`handle_sales_objection`/`email_sequence_skill.generate_reply_suggestion`), the latter has a real personalized-template fallback and is the safer of the two. `email_proofreader`/`agentmail_skill.classify_reply_intent` are the best-covered (real unit tests exist for their dead-LLM paths) and both fail **closed** (block/reject) rather than open.
- **Real bugs found while reading (not previously known)**:
  1. `gmail_skill.py::process_incoming_email` — undefined `logger` (module never imports `logging`); will raise `NameError` on the hard-bounce path.
  2. `sheets_sync.py::sync_lead_outcome_to_sheets` — calls `.value` directly on an un-awaited `asyncio.to_thread(...)` coroutine; will raise `AttributeError` if that exact branch (Sheets configured + `details` truthy) is exercised.
  3. `crawl_skill.py` — `crawl4ai` is not installed in this environment, so `elite_scrape`/`get_crawler` are currently dead code (raise `RuntimeError` if called), independent of any key.
- **Test coverage gaps**: of the 51 skills, only 4 have any direct/indirect test coverage today (`email_proofreader`, `agentmail_skill`, `calendar_skill.create_event`, `lead_gen_v3`/`smart_scraper` via import-only assertions in `test_hermesclaw.py`, `cal_booking` webhook handlers, `approval_workflow`). The other ~47 have zero unit tests — this matches Mark's stated intent to add full unit tests per skill in a later phase.
- **pytest baseline**: `python -m pytest tests -q` → **124 passed**, 28 warnings, 0 failed (re-confirmed at both the start and end of this audit). Note: this differs from the "98 passing baseline" figure in `CLAUDE.md` — worth updating that doc since 124 is the current, reproducible number.
